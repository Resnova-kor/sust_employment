# 웹앱 UI/UX 공통 규칙

다른 웹앱(관원 관리 프로그램)을 만들며 정한 화면 규칙 중 **여러 웹앱에 공통으로 쓸 수 있는 것**을 모은 문서.
`CLAUDE.md`에서 가져와(@) 매 세션 읽는다. 화면을 새로 만들거나 고칠 때 이 규칙을 따른다.

**이 프로젝트에 적용할 때**
- `CLAUDE.md`의 규칙과 다르면 **`CLAUDE.md`가 우선**(예: 폭 흔들림 방지는 `scrollbar-gutter` 대신 이미 쓰는 `html{overflow-y:scroll}` 유지, 색은 학교 디자인 시스템).
- 이미 있는 화면을 이 규칙에 맞추는 큰 정리는 따로 요청받았을 때만, 단계 계획을 먼저 보여 주고 승인받은 뒤 한다. 평소에는 고치는 곳부터 맞춘다.
- 12절 자동 검사 스크립트는 아직 없다(만들면 여기 적기).

- 표시 없음 = 이 프로젝트에서 실제로 써 보고 정한 규칙
- ➕ = 써 보지는 않았지만 함께 두면 좋은 규칙(추가 제안)

---

## 1. 요청을 반영하는 방법 (같은 요청이 반복되지 않게)

1. **요청 받은 곳만 고치지 않는다.** 같은 모양·같은 역할을 쓰는 곳을 모두 찾아(클래스·함수·문구로 grep) 함께 고친다.
2. **같은 모양은 공통 부품 하나로.** 화면마다 따로 만들지 않는다. 부품 목록(이름 → 쓰는 곳)을 문서에 표로 둔다.
3. **새 규칙은 바로 적는다.** 규칙 절과 '요청 체크리스트'에 적고, 가능하면 자동 검사도 추가한다.
4. **끝나면 세 가지 확인**: 자동 검사 위반 0건 → 캡처를 직접 열어 보기 → 체크리스트 다시 훑기.
5. **이름을 바꾸거나 없애면 옛 이름을 grep해서 0개**인지 확인(이벤트 리스너·CSS·검사 코드 포함). 바깥 클릭 리스너 하나를 놓쳐 창이 안 열리는 일이 실제로 있었다.
6. **누르면 열리는 것(창·고르기 칸)은 검사에서 실제로 눌러 본다.** 보이기만 확인하면 놓친다.
7. **'항목마다 다르다'는 일부만 골라 보지 말고 전체 자료로 확인.** 모든 항목을 넘기며 화면을 다 그린 뒤 측정한다.
8. **칸을 고정·한 줄로 만들었으면 글자 잘림(…)도 함께 확인.** 좁은 화면 열 너비는 전체 자료의 실제 내용 길이를 재서 정한다.
9. ➕ 요청을 받으면 먼저 "이 요청이 규칙 몇 번에 해당하는지 / 새 규칙인지"를 정하고 시작한다.

## 2. 디자인 단계값 (값을 고르지 말고 단계에서 고른다)

> **아래 숫자는 관원 관리 프로그램에서 정한 예시다.** 앱마다 목적과 읽기 좋은 크기가 다르므로, 새 앱을 만들 때 화면을 구성하면서 그 앱에 맞는 단계값을 정하고 그 앱의 `CLAUDE.md`에 규칙으로 적는다. 지킬 것은 숫자 자체가 아니라 **'몇 개의 단계만 정해 두고 그 안에서 고른다'**는 원칙이다.

| 항목 | 단계 | 예외 |
|---|---|---|
| 글씨 크기 | **13 · 15 · 17 · 22 · 28px** 다섯 단계 | 12px: 단축키 안내, 휴대폰 아래 메뉴, 숫자 배지. 인쇄는 따로 |
| 여백(안쪽·바깥·간격) | **4 · 8 · 12 · 16 · 24 · 32px** 여섯 단계 | 테두리 맞춤 1·2px, 40px 넘는 큰 값, auto |
| 버튼 높이 | **44 · 36 · 30px** 세 단계 | 휴대폰은 모두 44(누르기 쉽게), 입력 칸 옆 버튼은 입력 칸 높이, 큰 타일 |
| 알림 시간 | 모두 **4초** | |
| ➕ 모서리 둥글기 | 4 · 8 · 12px, 알약은 999px | |
| ➕ 그림자 | 2단계(떠 있는 칸 / 창) | |
| ➕ 겹침 순서(z-index) | 이름 붙인 단계만(메뉴 < 작은 창 < 창 < 알림) | |
| ➕ 움직임 시간 | 150ms(눌림·마우스) · 250ms(창 열기) | `prefers-reduced-motion`이면 끔 |

- 버튼 높이 쓰임새: **44** = 메뉴·위쪽 줄·화면 큰 버튼·탭 / **36** = 카드·창 안 버튼, 창 안 고르기 버튼, 거르기 탭 / **30** = 표 줄 안 버튼, 작은 탭, 칩
- 브라우저 기본 여백(`p`·`h1~h3`·체크박스·버튼)도 단계값으로 덮어 둔다. 안 덮으면 검사에 걸리고 화면마다 달라진다.
- 단계값은 CSS 변수로 한곳에 두고 그것만 쓴다(아래 13절 예시).

## 3. 통일성

- **이웃 서식 통일**: 같은 줄·같은 열·같은 묶음·같은 기능의 버튼(알약)은 글씨 크기·굵기·서체가 같게. 다르게 해도 되는 것은 강조뿐 — 고른 것(`.on`)·실행 버튼(`.pri`).
- **같은 줄 버튼은 같은 높이**, 버튼 사이 4px 이상.
- **같은 일은 같은 말** — 용어 사전을 문서에 둔다.
  - 창 닫기만: '취소'(입력 창) · '닫기'(보기 창)
  - 한 일을 무르기: '되돌리기'
  - 기록·설정 항목 없애기: '삭제' / 사람·큰 묶음: '휴지통으로'
  - 비슷한 두 뜻은 다른 낱말로 갈라 쓴다(예: '납부한 날' = 실제로 낸 날, '납부일' = 매월 정해진 날 — 한 낱말을 두 뜻으로 쓰지 않기)
- **자료에는 원래 값, 화면에는 짧은 이름**: 자료는 그대로 두고 보이는 이름만 줄인다(예: 자료 '계좌이체' → 화면 '계좌'). 표시 함수 하나로만 바꾼다.
- **화면 바깥 여백은 모든 화면 같게**, 화면 제목 위치도 모든 메뉴에서 같게.
- **같은 역할의 부품은 모든 화면에서 같은 크기**(예: 화면 위 요약 칸 — 이름 13px 위, 숫자 22px 아래, 한 줄 4칸).
- ➕ 아이콘은 한 세트만, 크기는 16·20·24px 세 단계.
- ➕ 날짜·숫자 표기 통일: 같은 해 '11/24', 다른 해 '25/12/31', 금액은 쉼표, 단위는 제목에.

## 4. 가독성

- **색은 상태에만 쓴다.** 예: 문제(미납·기한 지남) = 홍, 그 밖의 주의 = 주황, 완료 = 파랑. 장식용 색을 늘리지 않는다. 종류 구분 색이 필요하면 3가지 안에서 묶는다.
- **숫자는 고정폭**(`font-variant-numeric: tabular-nums`) — 표·합계에서 자릿수가 맞는다.
- **버튼·칩·알약 안 글자는 세로 가운데**(`align-items: center`, baseline 금지).
- **한국어는 낱말 중간에서 꺾지 않기**(`word-break: keep-all`).
- **해당 없는 칸은 회색 띠 대신 흐린 글자**, 같은 사유가 이어지면 첫 줄에 한 번만('1~9월 · 가입 전 (2026.10.31 가입)').
- **안내문은 한두 문장.** 길면 안 읽는다.
- **글씨 위계는 3단계 정도로 분명하게**(예: 핵심 숫자 22 > 보조 숫자 15 굵게 > 이름·탭 13).
- **링크처럼 보이는 것과 버튼을 섞지 않기**: 이름 링크는 평소 밑줄 없는 굵은 검정, 마우스를 올리면 파란 밑줄. 고치기는 밑줄 링크가 아니라 [수정] 버튼.
- **좁으면 짧은 글자로**: 긴 글자/짧은 글자 두 벌을 두고 폭에 따라 바꾼다(예: '영수증 발행' → 체크만 + 마우스를 올리면 설명).
- ➕ 글자·바탕 대비 4.5:1 이상(작은 글씨·흐린 글자도). 흐린 글자도 이 기준을 넘게.
- ➕ 색만으로 상태를 알리지 않는다 — 글자('미납')나 아이콘을 함께.

## 5. 레이아웃 안정성

- **넘겨도 자리가 그대로**: 다음 항목으로 넘길 때 이름 줄·사진·검색창·탭·표의 위치·크기·열 너비가 바뀌지 않게. 줄 높이도 항목마다 같게(표 칸 글은 한 줄).
- **자료가 바뀌어도 누른 줄이 그 자리에**: 정렬·거르기 결과가 바뀌는 조작(납부·취소 등) 뒤에도 방금 누른 줄을 그 자리에 두고, 달·거르기·정렬을 바꾸거나 화면을 다녀오면 그때 다시 정렬.
- **스크롤 막대 자리는 늘 비워 둔다**(`html { scrollbar-gutter: stable }`) — 스크롤이 생기는 화면으로 넘어가도 폭이 안 바뀐다. 그만큼 좁아지니 잘림 검사로 확인.
- **이중 스크롤 금지**: 화면 높이에 맞추는 화면은 페이지 스크롤 없이 표 안에서만 스크롤.
- **창 폭 범위(예: 1280~1920)에서 가로 넘침 없음.**
- **부품 안 배치는 화면 폭이 아니라 칸 폭 기준**(`@container`) — 글자 크기를 키워도 맞게 줄어든다.
- **글자 크기 설정 = 화면 전체 확대·축소**(예: 0.9 · 1 · 1.1 · 1.2). `html` zoom을 쓰면 vh·vw도 함께 바뀌므로 `calc(100vh / var(--z, 1))`처럼 배율로 나눈다. 검사는 작게·크게에서도 돌린다.
- **사용자 화면 기준을 숫자로 정해 둔다**(예: 1920×1080 모니터, 창 안쪽 1920×950에서 첫 화면이 스크롤 없이 12줄 보이기). 낮은 화면용 예외(줄 안 버튼 24px 등)도 미리 정한다.
- ➕ 불러오는 동안 자리 잡기(뼈대·고정 높이)로 화면이 튀지 않게.

## 6. 표

- **열 너비 고정**: `colgroup` + `table-layout: fixed`. 너비는 **비율(%)**로 — 남는 폭이 모든 열에 고르게 나뉜다. 버튼 묶음처럼 딱 맞아야 하는 열만 px로 두고 나머지 비율 합을 100%로.
- **정렬**: 짧은 값(번호·이름·날짜·상태·금액·버튼)은 가운데, 긴 설명만 왼쪽. 제목과 칸 정렬을 같게.
- **단위는 제목에**('금액(원)'), 칸에는 숫자만.
- **모든 표의 제목 줄은 같은 모양**(바탕·13px·굵기 600·높이 40px).
- **같은 자료를 보이는 두 표는 열 이름·순서가 같게.**
- **정렬 화살표는 정렬 중인 열에만**(나머지는 마우스를 올릴 때).
- 긴 표: 줄무늬, 해가 바뀌는 곳에 구분 줄, 맨 아래 합계 줄, 열 묶음 사이 구분선.
- CSS 우선순위 주의: 특정 표의 칸 규칙은 공통 표 규칙보다 강한 선택자로(`table.ptab td` > `table.t td`).
- ➕ 빈 표: "자료가 없어요" + 다음에 할 일 버튼 하나.

## 7. 버튼·입력

- **하나만 고르는 것은 버튼 묶음**(체크박스를 라디오처럼 쓰지 않기). 고른 것은 파란색.
- **금액 입력은 쉼표 자동**, `type=number` 쓰지 않기(쉼표 불가·휠로 값이 바뀜).
- **자주 쓰는 값은 빠른 입력 버튼**(예: 10~15만).
- **칸 이름은 칸 위, 같은 글씨(13px·보조색·500), 들여쓰기 없이**(`legend` 기본 들여쓰기도 없앰).
- **고치기는 줄마다 [수정] 버튼, 지우기는 수정 창 안 왼쪽 아래 빨간 버튼.** 목록에 지우기 버튼을 늘어놓지 않는다.
- **표 칸 바로 고치기**(자주 고치는 값만): 평소엔 글자, 마우스를 올리면 그림자 테두리 → 누르면 칸 옆 작은 창. 고르기는 바로 저장, 입력은 [취소]·[저장].
- **기본값을 똑똑하게**: 새 기록의 처음 값 = (미리 고른 값 →) 정해진 값 → 직전 값 → 없으면 입력부터 받기. '날짜 = 누른 날(오늘)'.
- **같은 기능을 여러 방식으로 만들지 않기**: +/− 버튼처럼 표를 복잡하게 하고 바로 기록을 바꾸는 방식은 피하고, 칸 누르기 하나로 통일.
- 단축키: 자주 쓰는 동작에 기능키(F1 검색, PgUp/PgDn 넘기기 등)와 화면 안 안내.
- ➕ 입력 검사는 칸을 떠날 때 칸 아래에 한 줄로(무엇이 틀렸고 어떻게 고치는지). 저장을 눌렀을 때 처음 알리지 않기.
- ➕ 창을 실수로 닫아도 입력한 내용이 남게(또는 닫기 전에 묻기).
- ➕ 보이는 크기가 작아도 누르는 영역은 넉넉히(휴대폰 44px).

## 8. 창·작은 창·알림

- **모든 창 머리에 닫기(X) 자동**(창 여는 함수 하나에서 넣는다).
- **입력 창 아래 = '취소' + 실행 버튼, 보기 창 = '닫기'.** Enter = 실행, Esc·바깥 누르기 = 닫기.
- **창 크기는 단계로**(예: 작게·보통 600px·크게). 같은 일을 하는 두 창은 같은 크기·같은 칸 순서.
- **칸 옆 작은 창 위치 규칙**: 누른 칸 바로 아래 4px(모자라면 위), 칸 가운데, 화면 밖으로 안 나감, 표를 굴리면 따라가고 표 밖으로 나가면 닫힘, 다시 그려도 같은 칸에 다시 붙음. 휴대폰에서는 쓰지 않고 보통 창.
- **지우기는 확인 창 대신 바로 + 알림 [되돌리기].** 확인 창은 습관적으로 눌러서 막는 효과가 작고, 되돌리기가 더 안전하고 빠르다.
- **알림은 한 가지 모양**: 4초, 버튼은 많아야 하나.
- **결과가 화면에 바로 보이면 알림 생략**(알림 피로 줄이기).
- ➕ 되돌릴 수 없는 일(전체 삭제·가져오기 덮어쓰기)만 확인 창, 버튼에 결과를 그대로 쓰기('485명 지우기').
- ➕ 창이 열리면 첫 입력 칸에 포커스, 닫히면 연 버튼으로 포커스 되돌리기.

## 9. 거르기·상태 표시

- **누르면 거르는 칩·칸은 지금 고른 것에 파란 테두리**(문제 거르기는 홍 테두리), 다시 누르면 전체.
- **거르기 안내는 한 줄**: '**확인할 메모**만 [해제]'. 거르기 이름은 짧게.
- **비슷한 숫자가 두 곳에서 다르면 이유를 보인다**(예: 메뉴 '미납 20' = 밀린 달 포함, 화면 '이번 달 미납 15' → 칸에 '밀린 달 포함 20명').
- **저장 상태를 늘 보이게**(저장됨/저장 중/저장 안 됨).
- **마지막에 보던 것 기억**(다시 열면 마지막 본 항목·화면).
- ➕ 비어 있음·불러오는 중·오류 세 상태를 모든 목록·화면에 만든다. 오류는 "무엇이 / 왜 / 어떻게"를 한 문장으로.
- ➕ 오래 걸리는 일(가져오기·백업)은 진행 표시 + 끝나면 결과 요약.

---

## 10. 좁은 화면·휴대폰

- **폭 기준(예: 900px 이하)에서 휴대폰 화면으로 전환** — 같은 자료, 다른 배치(표 → 카드).
- 휴대폰은 버튼 44px, 칸 옆 작은 창 대신 보통 창, 표 칸 버튼 대신 글자만 + [수정].
- 아래 메뉴는 자주 쓰는 3~4개만, 순서는 PC 메뉴와 같게.
- 가로로 긴 것(달 버튼 12개 등)은 줄바꿈 대신 가로로 밀기.
- ➕ 휴대폰 키보드에 맞는 입력 종류(`inputmode="numeric"`, `type="tel"`).

---

## 11. ➕ 접근성·키보드

- 마우스 없이 Tab·Enter·Esc만으로 모든 일을 할 수 있게, 포커스 테두리는 지우지 말고 `:focus-visible`로 보이게.
- 아이콘만 있는 버튼에는 `aria-label`과 마우스 설명(title).
- 알림·저장 상태는 `aria-live`로 화면 읽기 프로그램에도 알리기.
- 확대 200%에서도 가로 넘침 없이 쓸 수 있게(글자 크기 설정과 함께 검사).

## 12. 자동 검사 (Playwright로 모든 화면·창을 열어 측정)

규칙을 문서로만 두면 다시 어긋난다. 아래를 스크립트로 검사해 **'위반 0건'**을 완료 조건으로 둔다.

| 검사 | 내용 |
|---|---|
| 글씨 단계 / 작은 글씨 | 모든 보이는 글자의 계산된 크기가 단계값 안인지, 13px 미만이 없는지 |
| 여백 단계 | padding·margin·gap이 단계값인지 |
| 버튼 높이 | 버튼(라디오를 감싼 글자 칸 포함)이 세 단계 중 하나인지, 같은 줄 높이 차이 |
| 이웃 서식 | 같은 줄·열·묶음·기능 버튼의 글씨 크기·굵기·서체가 같은지 |
| 글자 잘림 | 버튼·알약·표 칸에서 `scrollWidth > clientWidth` |
| 붙은 버튼 | 버튼 사이 4px 미만 |
| 가로·세로 넘침 / 이중 스크롤 | 창 폭 범위 전부에서 페이지 넘침, 페이지와 표가 함께 스크롤되는지 |
| 칸 이름 | 창 안 칸 이름이 위·같은 글씨·들여쓰기 없음인지 |
| 표 | 제목 줄 모양, 제목·칸 정렬 일치, 같은 열 정렬, 칸 한 줄 |
| 자리 고정 | 전체 항목을 넘기며 이름 줄·검색창·표 위치·열 너비·줄 높이가 같은지 |
| 눌러 보기 | 여는 버튼을 실제로 눌러 창·고르기 칸이 열리는지 |
| 화면 비교 | 같은 역할 부품(제목 위치·요약 칸 크기)이 화면마다 같은지 |
| 배율 | 글자 크기 작게·크게, 여러 해상도에서 위 검사 반복 |
| 오프라인 | 외부 주소를 막고 열어 바깥 의존이 없는지(오프라인 앱일 때) |
| ➕ 대비 | 글자·바탕 대비 4.5:1 |
| ➕ 키보드 | Tab 순서로 모든 버튼에 닿는지, 포커스 테두리가 보이는지 |

- 검사마다 캡처를 남기고, **화면을 바꿨으면 캡처를 직접 열어 본다**(숫자 검사가 못 잡는 어색함이 있다).
- 실제 자료 대신 **이름·연락처를 가짜로 바꾼 익명 자료**로 검사하면 클라우드·다른 PC에서도 같은 결과를 얻고 개인정보가 깃에 들어가지 않는다.

## 13. 시작용 CSS 단계값 예시

## 14. 문서 운영

- 프로젝트 `CLAUDE.md`에 **① 일하는 방식 ② 공통 부품 표 ③ 규칙 ④ 요청 체크리스트 ⑤ 다시 묻지 않을 결정사항**을 둔다.
- 결정사항에는 이유를 한 줄 붙인다(나중에 같은 질문이 다시 나왔을 때 판단 근거).
- 버전: 큰 기능 = 앞 숫자, 작은 기능·수정·화면 개선 = 소수점. 기록은 기본 → 심화 순, 주제별 묶음.
