# 웹앱이 빈 화면으로 멈출 때 (크롬 · 파일 연결 · 브라우저 저장소)

PC에서 바로 여는 HTML 웹앱(주소가 `file://`)에 공통으로 쓰는 문서. 다른 웹앱 저장소에도 이 파일을 그대로 복사해 두고,
Claude에게 "docs/웹앱_시작_멈춤_대처.md 대로 적용해 줘"라고 하면 된다.

## 1. 증상
- 크롬에서 열면 **오류 없이 빈 화면**. 엣지·크롬 시크릿 창에서는 열린다. 가끔 저절로 다시 열리기도 한다.
- 2026-11 취업 통계(v4.4·v4.5)에서 실제로 겪음. 다른 PC의 다른 웹앱에서도 비슷한 일이 있었다.

## 2. 원인 (취업 통계에서 확인한 것)
- 앱은 '데이터 파일 열기'로 고른 JSON 파일의 **연결 정보(FileSystemHandle)를 브라우저 저장소(IndexedDB)에 기억**해 두고, 켤 때 `queryPermission()`으로 "아직 이 파일에 써도 되나"를 묻는다.
- 크롬이 이 질문에 **대답 없이 멈추는** 경우가 있다. 앱이 그 대답을 무작정 기다리면 화면을 그리지 못해 빈 화면이 된다.
- 시크릿 창·엣지는 그 연결 정보가 없어서(저장소가 따로라서) 이 단계를 건너뛰므로 열린다.
- 멈추는 이유는 확실하지 않다. 데이터 파일을 다른 폴더로 옮기거나 복사한 뒤 예전 연결이 남아 있을 때 의심된다.
- 같은 방식으로 브라우저 저장소(IndexedDB) 자체가 멈출 가능성도 있어 함께 대비한다.
- 크롬은 `file://`로 연 웹앱들의 저장소를 **한곳에서 같이 쓴다.** 그래서 아래 코드는 어느 앱 화면에서 실행해도 모든 로컬 웹앱의 파일 연결을 함께 검사한다.

## 3. 바로 푸는 법 (사용자가 직접)
1. 빈 화면 탭에서 F12 → **Console** 탭.
2. 붙여 넣기가 막혀 있으면 `allow pasting`을 직접 입력하고 Enter.
3. **검사**(읽기만 함): 아래를 붙여 넣고 Enter → 10초쯤 기다리기. '← 원인'이 찍힌 줄이 범인이다.

```js
(async()=>{const T=(p,ms)=>Promise.race([Promise.resolve(p),new Promise(r=>setTimeout(()=>r('⏱'),ms))]);const dbs=await T(indexedDB.databases(),3000);if(dbs==='⏱'){console.log('브라우저 저장소 목록 읽기가 3초 넘게 멈춤 ← 원인');return}console.log('저장소:',dbs.map(d=>d.name).join(', ')||'(없음)');let n=0;for(const{name}of dbs){const db=await T(new Promise((ok,no)=>{const r=indexedDB.open(name);r.onsuccess=()=>ok(r.result);r.onerror=()=>no(r.error)}),3000);if(db==='⏱'){console.log(name,'열기가 3초 넘게 멈춤 ← 원인');continue}for(const s of db.objectStoreNames){const hs=await T(new Promise(ok=>{const out=[],c=db.transaction(s).objectStore(s).openCursor();c.onsuccess=()=>{const x=c.result;if(!x)return ok(out);if(x.value instanceof FileSystemHandle)out.push([x.key,x.value]);x.continue()}}),5000);if(hs==='⏱'){console.log(name,'›',s,'읽기가 5초 넘게 멈춤 ← 원인');continue}for(const[k,h]of hs){n++;const q=await T(h.queryPermission({mode:'readwrite'}),2000);console.log(`${name} › ${s} › ${k} (${h.name}) 권한 확인:`,q==='⏱'?'2초 넘게 대답 없음 ← 원인':q)}}db.close()}console.log(`검사 끝 (파일 연결 ${n}개)`)})()
```

4. **조치**: '권한 확인: 2초 넘게 대답 없음'이 나왔으면 아래를 붙여 넣고 Enter. **멈춘 파일 연결만** 지우고, 학생·관원 자료 같은 다른 저장 내용은 건드리지 않는다.

```js
(async()=>{const T=(p,ms)=>Promise.race([Promise.resolve(p),new Promise(r=>setTimeout(()=>r('⏱'),ms))]);let n=0;for(const{name}of await indexedDB.databases()){const db=await new Promise((ok,no)=>{const r=indexedDB.open(name);r.onsuccess=()=>ok(r.result);r.onerror=()=>no(r.error)});for(const s of db.objectStoreNames){const hs=await new Promise(ok=>{const out=[],c=db.transaction(s).objectStore(s).openCursor();c.onsuccess=()=>{const x=c.result;if(!x)return ok(out);if(x.value instanceof FileSystemHandle)out.push([x.key,x.value]);x.continue()}});for(const[k,h]of hs)if(await T(h.queryPermission({mode:'readwrite'}),2000)==='⏱'){await new Promise(ok=>{const t=db.transaction(s,'readwrite');t.objectStore(s).delete(k);t.oncomplete=ok});n++;console.log(`지움: ${name} › ${s} › ${k} (${h.name})`)}}db.close()}console.log(n?`멈춘 파일 연결 ${n}개를 지웠어요. 새로 고침(F5) 후 데이터 파일을 다시 골라 주세요.`:'멈춘 파일 연결이 없어요.')})()
```

5. F5로 새로 고침 → 앱에서 **데이터 파일 열기**로 지금 쓰는 데이터 파일을 다시 고르고, 권한 창에서 '허용'(가능하면 '방문할 때마다 허용').

- 검사에서 '열기/읽기가 멈춤 ← 원인'(저장소 자체가 멈춤)이 나오면, 크롬을 완전히 닫았다가(작업 관리자에서 크롬이 남아 있지 않은지 확인) 다시 연다. 그래도 안 되면 저장소 비우기가 필요하다. 이때는 **브라우저 안에만 있는 자료가 지워지므로** 모든 앱의 데이터 파일이 최신인지 먼저 확인하고 Claude에게 단계별로 물어볼 것.
- 앱이 파일 연결을 다른 자료 안에 넣어 저장하는 경우(예: `{ handle, name }`), 검사가 '파일 연결 0개'로 나온다. 그때는 그 앱 코드를 보고 맞춰야 한다.

## 4. 앱 코드 보완 (Claude가 각 웹앱에 적용할 것)
목표: **크롬이 대답하지 않아도 정해진 시간 뒤에는 화면을 그리고, 데이터 파일로 계속 일할 수 있게.** 취업 통계 v4.6에 적용한 방식.

1. 시간 한도 도구 하나를 둔다.
   ```js
   const TIMEOUT = Symbol('timeout');
   const withTimeout = (p, ms) => Promise.race([Promise.resolve(p), new Promise((r) => setTimeout(() => r(TIMEOUT), ms))]);
   ```
2. **파일 권한 확인**(`queryPermission`)은 2초 한도. 시간을 넘기면 '연결 멈춤'으로 표시하고 `false`를 돌려준다.
   `requestPermission`(사용자가 권한 창에 답하는 것)에는 한도를 두지 않는다 — 사람이 답하는 시간이라서.
   ```js
   const q = await withTimeout(h.queryPermission({ mode: 'readwrite' }), 2000);
   if (q === TIMEOUT) { S.permStuck = true; return false; }
   ```
3. **시작할 때 저장소 읽기**(`IDB.get`)는 3초 한도. 넘기면 '저장소 멈춤'으로 표시하고 자료 없이 화면을 그린다.
4. **저장**: 저장소 쓰기도 3초 한도. 한 번 멈추면 그다음부터는 저장소를 건너뛰고 **데이터 파일에는 바로 저장**한다(파일 저장이 저장소 쓰기 뒤에 막히지 않게).
5. **화면 안내 줄**
   - 연결 멈춤: "크롬이 데이터 파일 연결 확인에 대답하지 않아요. 파일을 다시 골라 주세요" + [데이터 파일 열기]
   - 저장소 멈춤: "브라우저 저장소가 대답하지 않아 보관본은 쓸 수 없어요(데이터 파일 저장은 돼요). 크롬을 완전히 닫았다가 다시 열어 보세요."
6. **[다시 연결]** 버튼은 '연결 멈춤'이면 권한을 다시 묻지 말고 파일 고르는 창을 연다. 새로 고르면 '연결 멈춤' 표시를 지운다.

## 5. 시험 방법 (Playwright)
- 실제 크롬 멈춤은 재현이 어려우므로 **흉내**로 시험한다. 페이지가 열리기 전에(`addInitScript`) 다음을 넣는다.
  - 연결 멈춤: `FileSystemHandle.prototype.queryPermission = () => new Promise(() => {})`
  - 저장소 멈춤: `IDBFactory.prototype.open = function () { return {}; }`
- 파일 연결은 `navigator.storage.getDirectory()`로 만든 가짜 파일 핸들을 저장소에 넣어 만든다. 이 기능은 `file://`에서 안 될 수 있으니 `python -m http.server`로 열어서 시험한다.
- 확인할 것: 보완 전 버전은 빈 화면(재현) / 보완 후 2~3초 안에 화면 + 안내 줄 / [데이터 파일 열기]가 파일 고르는 창을 엶 / 정상일 때는 지연·안내 줄 없음 / 저장소가 멈춰도 파일 저장은 바로 됨.
- 실제 학생·관원 자료로 시험하지 말 것(익명 가짜 자료 사용).
